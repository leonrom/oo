Расширение использования стандартного аудиоплейера

1. Общие сведения

Модуль snd входит в библиотеку Olga7  и добавляет к использованию стандартного аудиоплейера (тега <audio>) следующие возможности:
  • подключение вызова аудио-файлов к любым (img, p, span и т.д) тегам страницы (в дополнение к стандартному тегу <audio>);
  • использование именованных ссылок в адресах аудио-файлов (например, при их нахождении на различных серверах);
  • возможность отложенной загрузки аудиофайлов до момента обращения к ним, что снижает нагрузку на браузер при большом их количестве;
  • синхронизация звучания,- когда запуск нового аудио-файла автоматически прекращает обработку предыдущего (как в <audio>, так и остальных тегах);

Скрипт обрабатывает как теги <audio>), как и любые иные теги, у которых задан класс olga_snd, находящиеся в областях действия инициализации библиотеки.

Скрипт может использоваться как в составе библиотеки com!.js, так и автономно. В последнем случае автоматически подключается урезанная версия библиотеки и несколько ограничивается функционал. В частности нельзя использовать составные именованные ссылки

Подобно остальным скриптам библиотеки этот может быть подключен не только к отдельным HTML-страницам, но и функционировать внутри Blogger'а, в частности на шаблоне Dynamic View.

2. Подключение скрипта

1.1. Автономное подключение

Выполняется вызовом непосредственно файла "./o7/snd/snd.js": 

<script type="module" src="http://localhost/oo/o7/snd/snd.js" 
    data-consts="
        back_time= 0.6с, 			
        ау_длинный =../../media/audio/Clouds.mp3;
        ау_средний=../../media/audio/Ceza1-25.mp3;
        ау_короткий=../../media/audio/yapma.mp3;
    ">
</script>

Здесь в теге <script> атрибут type="module" указывает на модульную структуру js-файлов, а в атрибуте data-consts заданы (переопределены) параметры, которые могут быть использованы в скрипте. В частности заданы именованные адреса аудиофайлов.

1.2. Подключение в составе библиотеки

Выполняется вызовом ядра "./o7/index.js" с указанием имени модуля в атрибуте data-modules: 

<script type="module" src="http://localhost/oo/o7/index.js" 
    data-modules="snd" 
    data-consts="
        // другие константы иных модулей библиотеки
        back_time= 0.6с, 
        media =  + ../media;
        моя_папка = media + /audio;
        ау_длинный =моя_папка + /Clouds.mp3;
        ау_средний=моя_папка+/Ceza1-25.mp3;
        ау_короткий=моя_папка+/yapma.mp3;
    ">
</script>

В примере показан пример использования составных именованных ссылок, которые недопустимы при автономном подключении.

Используемый библиотекой атрибут data-modules содержит список подключаемых модулей (в примере - snd есть единственный).
Здесь data-consts является общим для всех модулей библиотеки и содержит константы в частности модуля snd.

3. Обработка тегов веб-страницы

Целями подключения модуля к тегам есть синхрониациюязвучания аудио и возможность задания именованных ссылок н аудио-файлы. А также визуализация звучания и обеспечение ленивой загрузки аудио для облегчения работы браузера.

3.1. Подключение к произвольным тегам

Подключение к любым тегам страницы выполняется заданием им класса olga-snd с квалификаторами. Такое задание не обязательно для тегов <audio> которые будут обрабатываться в любом случае.

Пример подключения файла (именованная ссылка) ау_короткий к тегу <p>: 

	<p class="olga-snd:L:ау_короткий"">класс "olga-snd:L:ау_короткий"</p>

После olga-snd должны следовать 2 квалификатора, разделённые символом ':'.

Первым (нобязательным) может быть строка содержащая 0 или более больших латинских букв и задающее как управление звучанием:

  • 'C' — звучание начнётся после клика по тегу (умолчание)
  • 'A' — звучание начнётся при наведении курсора (также и по клику).
  • 'O' — как 'A', но звук прекращается после увода курсора с тега
  • 'L' — звучание зацикливается;

так и его визуализацию:

  • 'S' — при проигрывании вокруг тега появляетя 'ореол '
  • 'W' — при проигрывании тег будет (пытаться) 'покачиваться'

Кроме использования 'W' и/или 'S' для визуализации изменяется форма курсора при подготовке (cursor: progress;) и во время (cursor: wait;) звучания

W рекомендуется использовать в основном для тегов <img>. Потому, что при его задании в в класс тега будет автоматически вписано "display: inline-block;", которое и так по-умолчанию задано для <img>, однако для иных тегов оно может изменить их ожидаемое отображение.

Вторым (обязательным для всех тегов, кроме <audio>) является ссылка на аудо-файл. Удобно использовать именованные ссылки.

Загрузка аудо-файлов выполняется только после наведения курсора на тег. Содержимое файлов сохраняется в 2-х локальных буферах - один для коротких, другой для длиных файлов. Предусмотрен контроль переполнения буферов и удаляютя самые старые аудио. Если для тега в буфере уже содержится аудио с таким же url'ом, то оно не загружается повторно.

3.2. Управление звучанием

Начинается звучание (в общем случае) кликом по тегу. Также при задании (квалификатора) 'O' или 'A' звучание будет начинаться по наведению курсора на тег.

Если при инициализации звучания нажата клавиша Shift то скорость воспроизведения изменится пропорционально константе shift_speed.

Прекращается звучание:

  • кликом на странице (на любом элементе)
    • >
  • уводом курсора со страницы с звучащим тегом
    • >
  • при задании 'O' - уводом курсора со звучащего тега
    • >
  • при созникновении события 'o-stopSound' (сгенерированного иным модулем)
    • >

Если с момента остановки курсор не покидал звучавший тег, то при последующем клике по нему звучание будет продолжено чуть ранее (на величину back_time) того места, где остановилось.

3.3. Подключение к тегам <audio>

Для таких тегов можно не задавать класс olga-snd. В этом случае модуль его всё равно включает в пул синхронизации звучания с остальными тегами.

Задание olga-snd без квалификаторов (и без символов ':') добавляет :

  • изменение курсора при звучании тега
  • прекращение звучания при покидании курсором текущей страницы

В первом квалификаторе учитываются только 'S' и'W'.

Во втором квалификаторе может быть задана (еще одна) ссылка на аудио-файл. Алгоритм обработки ссылок:

  • составляется (м.б. пустой) список ссылок из вложенных тегов <source>
  • в список добавляется ссылка из самого тега <audio>
  • также в него добавляется ссылка, заданная 2-м квалификатором
  • первая доступная из списка ссылка и принимается к звучанию

Ссылки в тегах м.б. в именованном виде. Чтобы не позволить браузеру их сразу обрабатывать и отложить загрузку аудио-файлов аж до их востребованности ссылки м.б. замаскированы. Для этого вместо атрибута src в теге можно использовать _src или data-src

Т.е. при определении ссылки в теге сначала ищется атрибут src, а при его отсутствии - _src, а при их отсутствии - data-src. Если ссылка задана в именованном виде, то она перекодируется в полноценный url. После этого:

  • ищется в буфере уже загруженных аудио-файлов
  • при отсутствии - загружается в буфер
  • присваивается атрибуту src

Именованные ссылки не следует сразу задавать атрибуту src т.к. браузер начнет излишне 'дёргаться' пытаясь открыть их.

4. Атрибуты модуля snd

Модуль использует атрибут data-consts в вызывающем теге <script>.

Атрибут может содержать параметры управления звучанием:

  • shift_speed — относительная скорость проигрывания аудио при нажатой клавише shift в момент начала звучания,- по умолчанию= 0.5;
  • back_time — возврат по времени в секундах при возобновлении звучания после паузы,- по умолчанию= 0.3с.

Также атрибут data-consts может содержать именованные ссылки на аудио-файлы,- их примеры см.в п.1.1 и п.1.2.

5. Анализ ошибок

При возникновении ошибки программа затемнит изображение аудио-тега, а в его атрибут title пропишет краткую информацию об ошибке,- которая будет всплывать при последующих наведениях курсора. Если причиной ошибки могло быть плохое интернет-соединение, то следует повторять попытки озвучки.

Если же проигрывание аудио не выполняется и/или в console.log выдаётся (уже после сообщения об инициализации" модуля snd) 404-я ошибка, то в HTML-документе нужно найти и проанализировать все те строки, в которых определяется этот url.

Для облегчения поиска причин ошибок следует задавать атрибут id для обрабатываемых тегов. В листинге программы раскрыть группу сообщений "Выполнено подстановок для тегов",- для данного скрипта и для ref.js, если он подключен. В открывшихся таблицах проверить правильность сформированных url'ов. Вплоть до ручной компоновки результирующего url и проверки его в отдельном окне браузера.
