Вставка html-файлов или их фрагментов в текст загруженного документа

Скрипт несколько расширяет возможности тега <iframe> при вставке html-файлов или их фрагментов, находящихся в одном домене с основным документом.

В отличие от большинства скриптов библиотеки Olga7  данный скрипт может использоваться автономно,- как без подключения ядра com!.js так и при его подключении, но при этом скрипт д.б. размещен выше скрипта ядра.
Тег <script> вызова модуля inc должен находиться прежде вызовов остальных скриптов быблиотеки.

Вставка выполняется добавлением содержимого (или его части) считанного файла к содержимому тега, содержащего атрибут 'o_include'. Вставляться может как весь загруженный текст (т.е. секцияг <body>), так и лишь содержимое некоторого тега, определяемого селектором.

Во вставляемом файле игнорируется содержимок секции <head>, поэтому она может отсутствовать.

Считывание файла реализовано с использованием 'веб API интерфейса' XMLHttpRequest. На загрузку файлов с "чужиих доменов" действуют ограничния 'CORS policy'.

Чтобы вставить только часть считываемого файла (т.е. содержимого его тега <body>) следует после атрибута 'o_include' написать '?' или '!' и селектор начинающийся символом:

  • [ - выбирается тег, удовлетворяющий querySelectorAll() для селектора
  • # - выбирается тег с указанным далее id
  • . - выбирается тег, содержащий указанный далее класс
  • иначе - выбирается тег с таким наименованием

Классы могут содержать квалификаторы (черз ':'), каждый из которых должен присутствовать в теге

Вставляются (т.е. последовательно добавляются) содержимые всех найденные по селектору тегов. Если разделителем указан '!', то вставляются сам найденный тег и его содержимое; иначе (если указан '?') - только содержимое. Для тега <body>> всегда вставляется только содержимое.

Если же ни один тег не находится - записывается сообщение об ошибке: "inc: обработка 'CInclude' - есть ошибки".

Теги <script> из вставляемых фрагментов НЕ обрабатываются (в этой версии).

Вставка может выполняться рекурсивно, т.е. скрипт обрабатывает ссылки во вставляемых фрагментах.

Посмотреть реализацию подгрузки разных фрагментов (из двух разных файлов) можно здесь, где у атрибута o_include заданы различные квалификаторы.

Вставляются содержимые всех тегов (из загруженного файла), удовлетворяющие заданному выражению. В примере были показаны ставки в теги div, однако можно вставлять в любые теги (дополняя при этом их содержимое).

Разумеется, сами файлы inc1.html и inc2.html считываются только по одному разу. Их содержимое можно увидеть в протоколе в раскрывающемся сообщении 'Содержимое прочитанного ...'

Ядро библиотеки проверяет наличии данного скрипта и тегов с атрибутои o_include и, при их наличии,- модуль inc выполняется в первую очередь, независимо от гположения его скрипта. При подключении скрипта совместно с иными библиотечными скриптами он должен располагаться прежде них.

Скрипту м.б. заданы атрибуты getall и isfinal.

Умалчиваемое значение для getall= 'true'. Если задать 'false', то вставка (и загрузка файлов) будет только в те теги, у которых у них самих, так и у их предков НЕ задан стиль display = 'none'. Это может снизить трафик, однако при изменении их видимости следует генерировать событие window.dispatchEvent(new CustomEvent('o_include')) для (вероятной) вставки новых фрагментов.

Умалчиваемое значение для isfinal= '1'. Если задать '0', то скрипт не будет гененрировать сообщение 'o_scriptDone' об окончании своей работы и инициация иных модулей библиотеки приостановится. При этом такое сообщение должно будет быть сделано где-то (см. пример ) в вызывающем модуле: вызовом

window.o7.C.E.DispatchEvent('o_scriptDone', 'inc')

После загрузки файлов, указанных в атрибутах o_include скриптом всегда генерируется window событие o_incReady, которое должно использоваться вместо (вместе) сообщения DOMContentLoaded.

Если событие o_incReady происходит после события o-inited (т.е. после инициализации всех модулей), то считается, что произошло обновление страницы и скрипты (все, кроме o5init) инициализируются повторно.
